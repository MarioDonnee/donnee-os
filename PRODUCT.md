# Product

## Register

product

## Users

Donnée OS is used by Donnée operators, consultants and managers who need to coordinate clients, projects and tasks inside one operational workspace. The user is usually inside a work session, reviewing status, creating records, checking execution and keeping the consultancy workflow coherent.

The interface serves repeated operational use. It should support quick scanning, confident creation of records and clear movement between dashboard, clients, projects and tasks.

## Product Purpose

Donnée OS exists to be the internal operating system for Donnée. It centralizes clients, projects, tasks, dashboards, activity logs and metadata-driven workflows so the team can manage delivery with more intelligence and less fragmentation.

Success means the core product flow works end to end: create clients, link projects, create tasks, inspect operational metrics and preserve auditability through backend logs.

## Brand Personality

Premium, intelligent, experimental.

The product should feel like an internal command surface for a consulting company that builds intelligent systems. It should be calm enough for daily work, but distinctive enough to avoid generic SaaS blandness.

## Anti-references

Do not make Donnée OS look like a default Bootstrap admin panel, a generic SaaS template, a CRM clone or a marketing landing page.

Avoid bright corporate blue dashboards, flat white enterprise tables, overdecorated AI-product gradients and decorative visual effects that do not improve operational clarity.

Do not expand the MVP into advanced AI, automation, billing, finance, ERP or complex workflow engines unless explicitly requested.

## Design Principles

1. **Operational intelligence first.** Every screen should make current work easier to scan, create or decide on.
2. **Premium without spectacle.** The interface can be dark, atmospheric and distinctive, but the work surface must remain readable and restrained.
3. **API-driven truth.** Statuses, priorities and operational categories should come from backend metadata when endpoints exist.
4. **Incremental product flow.** Build clients, projects, tasks and dashboard workflows before auth, automation or advanced intelligence.
5. **Distinctive, not generic.** Use Donnée's purple-black identity deliberately; avoid default admin patterns and template-like composition.

## Accessibility & Inclusion

Target practical WCAG AA behavior for contrast, focus visibility and keyboard-friendly controls. Preserve clear labels, readable hierarchy and responsive layouts. Motion should be restrained and nonessential; users should not need animation to understand state.
